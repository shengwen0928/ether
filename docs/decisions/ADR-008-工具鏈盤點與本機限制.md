狀態：草案／待批准

# ADR-008：工具鏈盤點與本機限制（node 24 有、flutter／go／docker 無）

- **狀態**：已決定（草案／待批准）
- **日期**：2026-11-25（Phase 00，環境實測）
- **依據**：SPEC-SOURCE.md「環境實情」

## 問題

本機 Linux VM 的工具鏈現況為何？Phase 00 文件與 Phase 01 驗證應如何面對本機限制？

## 實測結果（2026-11-25，本機 VM）

| 工具 | 結果 |
|---|---|
| node | v24.22.1（有）；npm 有 |
| flutter | 無 |
| go | 無 |
| docker | 無 |
| psql | 無 |
| redis-server | 無 |
| 基礎設施／叢集命令列工具 | 無（已由 OpenTofu／Coolify 方向取代，見 ADR-009／ADR-013；本機亦無） |

作業系統：Linux（`htch-runtime` 核心，x86_64）。iOS 建置在 Linux 上不可能，須走 macOS CI（見 ADR-003）。

## 選項

| 選項 | 說明 |
|---|---|
| A. 如實記載限制，驗證走 CI 或有工具的環境 | 誠實、可驗證 |
| B. 假裝工具鏈齊全，在本機寫「已驗證」 | 禁止：未驗證不宣稱（SPEC-SOURCE.md §27） |
| C. 在本機安裝全部工具鏈後再開始 | 未經批准不得擅自改變 VM 環境；且 iOS 仍不可能在本機建置 |

## 決定

選 A：文件如實記載本機限制；凡須 flutter／go／docker 的驗證（Docker Compose 啟動／連線／上傳／訊息／AI 切換／LiveKit／監控），一律標為「待 CI 或有 Docker 的環境驗證」，不得寫已驗證。Phase 01 的建置與測試驗證以 CI（GitHub Actions，含 macOS runner）為準，本機只做文件與靜態檢查。

## 理由

1. SPEC-SOURCE.md 環境實情明文要求文件如實記載，不得假裝工具鏈齊全。
2. 架構調整後，Docker Compose 為部署組合單位，本機無 docker 即本機無法驗證部署——此缺口必須明列，不得以文件推導代替驗證。

## 後果

- 全部 Phase 00 文件的驗證狀態皆為「草案／待批准」，無任何「已驗證」宣稱。
- CI 環境的工具版本固定（flutter／go／docker 版本待 Phase 01 定案），不得用浮動版本。
- 本決定不涉及花錢或綁卡；CI runner 成本待查證（見 ADR-003／ADR-013）。
