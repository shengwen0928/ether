# ADR-009：免費開源替代總決策（全面替換付費服務）

- **狀態**：已決定（草案／待批准）；取代 ADR-002
- **日期**：2026-11-25 00:33（使用者架構調整指令）
- **依據**：SPEC-SOURCE.md 頂部「架構調整」一節（優先於舊技術棧）；使用者免費原則（不得新增付款方式）

## 問題

ETHER 應如何全面替換付費服務、改採免費及開源方案，同時不刪功能、不降級、不破壞 E2EE？

## 選項

| 選項 | 說明 |
|---|---|
| A. 全面替換為使用者指定的免費／開源對照（本決定） | 功能保留、成本結構改為自架＋仍可能付費項目明列 |
| B. 維持原付費參考架構 | 已被使用者指令取代（見 ADR-002 已取代狀態），不得繼續 |
| C. 部分替換、部分保留付費服務 | 未經使用者指定，不得擅自保留付費服務；任何保留皆須使用者決定 |

## 決定

選 A：依使用者指定的強制替換對照，全面改採免費及開源方案。舊服務名只准出現在比較文件（`docs/COST_OPTIMIZATION.md`，另冊），不得殘留在架構正文。功能不得刪、不得降級。

## 差異分析摘要

1. **成本結構改變，成本未消失**：自架方案把「按量付費」改為「主機＋頻寬＋人力維運」成本；仍可能付費項目須明列——網域、伺服器、簡訊 OTP、Apple Developer、Google Play 上架、外部 AI API、TURN 頻寬等——不得宣稱全系統零成本。正式部署成本待查證且為阻塞項。
2. **維運責任轉移**：備份、故障轉移、版本更新、安全更新、叢集化，皆由自架方承擔；原託管服務提供的 SLA 與自動化不再假設存在，須以維運文件與演練補齊（見 `SCALABILITY.md` §9）。
3. **功能保留的驗證責任**：每一項替換皆須證明功能未降級——Docker Compose 啟動／連線／上傳／訊息／AI 切換／LiveKit／監控，皆為「待 CI 或有 Docker 的環境驗證」（本機 VM 無 docker，見 ADR-008），不得寫已驗證。
4. **E2EE 不受影響**：替換皆在傳輸／儲存／部署層，E2EE 邊界（伺服器不可讀明文，見 `SECURITY_ARCHITECTURE.md` §7）不變；Keycloak 與 OpenBao 的引入不得改變金鑰材料的持有關係（伺服器不得持有可解密的私鑰）。
5. **AI 資源評估為新阻塞**：Ollama／vLLM 的模型須評估 CPU／RAM／GPU／VRAM，不得假設一般伺服器跑得動所有模型；模型清單與硬體需求待查證。
6. **TURN 頻寬為新風險**：LiveKit CE 自架後，TURN 中繼頻寬成為主要變動成本來源，見 ADR-011 的特別評估。

## 後果

- 架構正文（`docs/architecture/`）已全面改寫為新方案；舊服務名全文 grep 不得殘留（比較文件除外）。
- 本 ADR 不代使用者決定花錢或綁卡：仍可能付費項目的開通與付款，皆須使用者決定。
- 成本比較的完整數字分析屬 `docs/COST_OPTIMIZATION.md`（另冊），本 ADR 只定對照與原則，不編造額度與數字。
