狀態：草案／待批准

# ADR-004：外部憑證阻塞清單（未取得前只寫介面與 Adapter）

- **狀態**：已決定（草案／待批准）；阻塞持續中
- **日期**：2026-11-25（Phase 00）
- **依據**：SPEC-SOURCE.md 手冊 A（未取得的第三方憑證不得當已完成整合）、§27 第 11 條、架構調整一節

## 問題

哪些外部服務憑證是 ETHER 整合的阻塞項？未取得憑證前，相關功能應做到什麼程度？

## 選項

| 選項 | 說明 |
|---|---|
| A. 未取得憑證前只寫介面與 Adapter，並標記阻塞 | 符合手冊 A：先做可獨立部分並標記阻塞，不得假裝成功 |
| B. 先以假憑證／Mock 冒充整合完成 | 禁止：SPEC-SOURCE.md §27 不得用假 API 冒充後端、不得用固定假資料冒充功能 |
| C. 等全部憑證到齊才開始 | 不可行：會阻塞全部可獨立進行的架構與介面工作 |

## 決定

選 A。阻塞清單如下（取得狀態皆為「未取得／待查證」，不得寫已完成）：

| 阻塞項 | 用途 | 未取得前的可做範圍 |
|---|---|---|
| FCM 憑證 | Android 推播 | 推播扇出介面、事件訂閱、投遞紀錄模型；不得宣稱 Android 推播可用 |
| APNs 憑證 | iOS 推播 | 同上（iOS 側）；不得宣稱 iOS 推播可用 |
| Apple Sign-In 憑證 | Apple OAuth 登入 | OAuth Adapter 介面、Keycloak 整合介面；不得宣稱 Apple 登入可用 |
| Google OAuth 憑證 | Google 登入 | 同上；不得宣稱 Google 登入可用 |
| 簡訊 OTP 供應商憑證 | 手機驗證碼 | 驗證碼流程介面與 Adapter；簡訊為仍可能付費項目，成本待查證 |
| LiveKit／TURN 憑證與部署 | 通話媒體與穿透 | LiveKit CE 自架介面、信令流程、TURN 臨時憑證核發介面（見 ADR-011）；TURN 頻寬為仍可能付費項目 |
| 付款供應商憑證 | 付款整合 | Payment Integration Adapter 介面、交易紀錄模型；不得宣稱付款可用，不得自行儲存信用卡完整資訊 |
| 檔案掃描方案 | 媒體安全掃描 | 掃描介面（Worker 呼叫點）與未掃描不得分發的狀態機；方案本身待查證 |
| 外部 AI API 金鑰（如選用外部路徑） | 外部 AI 擴充 | Provider Adapter 介面；本機路徑（Ollama／vLLM）優先，外部路徑為可選擴充 |

## 理由

1. 手冊 A 明文：缺少憑證／服務／資訊時先做可獨立部分並標記阻塞，不得假裝成功。
2. Adapter 隔離（見 `SYSTEM_ARCHITECTURE.md` §2）：商業邏輯不得直接依賴特定供應商 SDK，憑證到齊後只需接線 Adapter，不得重寫商業邏輯。
3. 全部憑證皆經 OpenBao 管理（見 `SECURITY_ARCHITECTURE.md` §6），不得入 Git、不得寫入文件範例值。

## 後果

- 每個阻塞項須在階段驗收報告中明列「未完成項」，不得標為完成。
- 本 ADR 不代使用者決定花錢或綁卡：簡訊、外部 AI、TURN 頻寬等仍可能付費項目，須由使用者決定後才申請／開通。
