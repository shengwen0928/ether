## 1. 五類區分

| 類別 | 定義 | 說明 |
|---|---|---|
| A．完全開源自架 | 開源授權，可自行部署於自有或租用伺服器，無按量計費的服務費 | 仍須自負伺服器成本（見 D 類重疊說明）；維運、備份、升級責任由營運方承擔 |
| B．免費額度 | 供應商提供的免費額度或免費方案，在額度內不收費 | 額度數字以官方當期公告為準，待查證；超出額度即收費或限流，須有監控與預警 |
| C．功能受限免費 | 免費方案可用，但功能、規模或支援受限 | 受限範圍須明列；受限功能不得以「免費版亦有」冒充完整功能 |
| D．需自負伺服器成本 | 自架方案，須自行負擔伺服器（含運算、儲存、頻寬）的持續性成本 | 伺服器成本金額待查證，取決於主機規格、區域、流量與備援設計 |
| E．仍須付費 | 無免費或開源等價替代，或替代無法完全滿足需求，仍須付費 | 金額待查證；須明列原因與替代嘗試 |

重疊說明：多數自架開源方案同時屬於 A 類與 D 類（軟體免費、伺服器付費）。下表以「主類別」標示，並以「伺服器成本」欄位標示 D 類重疊。不得以 A 類標示掩蓋 D 類成本。

## 3. 逐項分析

每項皆含：對應替代、功能差異、授權條款、是否自架、是否需額外硬體、免費額度限制、預估持續性成本、成熟度分析。非完全等價者，先分析差異，不得宣稱為等價替換。

### 3.1 容器編排：ECS Fargate → Docker Compose＋Coolify

- **對應替代**：Docker Compose（容器編排）＋Coolify（自架部署平台，含介面、自動部署、憑證與監控整合方向）。
- **功能差異（非完全等價）**：Fargate 為無伺服器容器運算，自動擴縮、按量計費、託管可用性；Docker Compose＋Coolify 為單機或有限多機編排，擴縮須手動或以額外機制處理，多區域與自動容錯能力較弱。Coolify 的多伺服器、備援與擴充能力，須以實測為準，不得假設與託管服務等價。
- **授權條款**：Docker Compose 與 Coolify 的授權，以官方儲存庫當期授權文件為準，待查證。
- **是否自架**：是。**是否需額外硬體**：否，沿用既有伺服器；規模擴大時須評估。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器成本，隨容器數量與流量而定）。
- **成熟度**：Docker Compose 為成熟的本機與小型部署工具；Coolify 為較新的自架平台，社群活躍但版本更迭較快，升級與相容性須以實測與版本固定策略管理。

### 3.2 關聯式資料庫：RDS／Aurora → PostgreSQL 自架

- **對應替代**：PostgreSQL 自架於伺服器，搭配 Docker Compose 部署、備份腳本與監控。
- **功能差異（非完全等價）**：託管服務提供自動備份、時間點還原、自動容錯移轉、讀取複本、自動修補；自架須自行實作備份、還原測試、主從複寫、容錯移轉與版本升級，維運責任與停機風險由營運方承擔。Aurora 的分散式儲存與讀寫擴充能力，自架無法直接等價。
- **授權條款**：PostgreSQL License（以官方當期文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否，儲存與備份規模擴大時須評估磁碟。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器＋儲存＋備份成本）。
- **成熟度**：PostgreSQL 為高度成熟的開源關聯式資料庫，社群與文件完整；自架部署的成熟度取決於營運方的備份與容錯實作，不得以資料庫本身的成熟度冒充部署架構的成熟度。

### 3.3 快取：ElastiCache → Valkey

- **對應替代**：Valkey（Redis 的開源分支方向，相容 Redis 協定與多數指令）。
- **功能差異**：託管快取提供自動容錯、備份、監控整合；自架 Valkey 須自行處理持久化、複寫、容錯與監控。Valkey 與 Redis 的指令相容性須以實測為準，不得假設全部用戶端函式庫與指令皆相容。
- **授權條款**：BSD-3-Clause（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否，記憶體規模擴大時須評估。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器成本，隨記憶體規模而定）。
- **成熟度**：Valkey 為較新的分支，社群成長中，長期維護與生態系須持續觀察；相容性與效能須以實測為準。

### 3.4 物件儲存：S3 → MinIO

- **對應替代**：MinIO 自架物件儲存，提供相容物件儲存 API 的介面。
- **功能差異（非完全等價）**：託管物件儲存提供多區域備援、極高的耐久性承諾、託管生命週期與整合服務；自架 MinIO 的耐久性取決於磁碟、糾刪碼設定與備份策略，不得以軟體本身宣稱與託管服務相同的耐久性。跨區域複寫、版本管理、生命週期規則，須自行設定與測試。
- **授權條款**：GNU AGPLv3（以官方儲存庫當期授權文件為準，待查證；授權義務須以法律意見確認，本文件不提供法律意見）。
- **是否自架**：是。**是否需額外硬體**：否，儲存容量擴大時須評估磁碟。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器＋磁碟＋頻寬成本）。
- **成熟度**：MinIO 為成熟的自架物件儲存，廣泛用於私有部署；授權條款的合規義務須特別注意。

### 3.5 搜尋：OpenSearch → Meilisearch

- **對應替代**：Meilisearch 自架搜尋引擎，用於好友、訊息、檔案、動態等全文搜尋。
- **功能差異（非完全等價）**：OpenSearch 為分散式搜尋與分析平台，支援大規模叢集、複雜聚合與日誌分析；Meilisearch 偏向輕量、快速的全文搜尋，單機或有限叢集為主，大規模分散式、日誌分析與複雜聚合能力較弱。E2EE 訊息的搜尋邊界不受搜尋引擎選擇影響（伺服器無法解密，見 E2EE 研究文件）。
- **授權條款**：MIT（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否，索引規模擴大時須評估。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器成本，隨索引規模而定）。
- **成熟度**：Meilisearch 為成熟的輕量搜尋引擎，文件與社群完整；大規模部署的效能須以實測為準。

### 3.6 憑證管理：Secrets Manager → OpenBao

- **對應替代**：OpenBao（開源憑證管理，Vault 的開源分支方向），用於 API Key、資料庫憑證、OAuth 憑證的集中管理。
- **功能差異**：託管憑證管理提供自動輪換、託管整合、稽核整合；自架 OpenBao 須自行處理高可用、備份、解封流程、輪換自動化與稽核。OpenBao 與 Vault 的相容性與生態系，須以實測為準。
- **授權條款**：Mozilla Public License 2.0（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器成本）。
- **成熟度**：OpenBao 為較新的分支，社群成長中，長期維護須持續觀察；憑證管理的正確設定為安全關鍵，不得以安裝完成代替安全驗收。

### 3.7 可觀測性：CloudWatch → Prometheus＋Grafana＋Loki

- **對應替代**：Prometheus（指標）、Grafana（視覺化與告警）、Loki（日誌），搭配 OpenTelemetry（追蹤與指標收集）。
- **功能差異**：託管監控提供整合式收集、託管儲存、自動告警整合；自架組合須自行組裝收集、儲存、保留、告警與儀表板，保留期限與儲存成本須自行管理。監控覆蓋範圍：API、WebSocket、資料庫、Worker、Media、AI（依架構調整指令）。
- **授權條款**：Prometheus 為 Apache-2.0；Grafana 與 Loki 為 GNU AGPLv3（皆以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否，日誌與指標保留量擴大時須評估儲存。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器＋儲存成本）。
- **成熟度**：三者皆為成熟的開源可觀測性組合，廣泛用於自架部署；組合的維運複雜度高於託管服務，須有專責維運流程。

### 3.8 內容分發：CloudFront → Cloudflare Free

- **對應替代**：Cloudflare Free 方案（DNS、內容分發、基礎防護）。
- **功能差異（功能受限免費）**：託管內容分發提供全球邊緣節點、按量計費的彈性頻寬、進階功能；免費方案的頻寬、功能、支援與服務等級受限，限制數字以官方當期公告為準，待查證。免費方案不得假設可支撐任意流量，流量上量後須評估升級或替代方案。
- **授權條款**：專有免費服務方案，服務條款以官方當期條款為準，待查證。
- **是否自架**：否。**是否需額外硬體**：否。
- **免費額度限制**：有，限制以官方當期公告為準，待查證。
- **預估持續性成本**：待查證（超出免費額度或升級方案的成本）。
- **成熟度**：Cloudflare 為成熟的託管服務商；免費方案的成熟度高，但功能受限，須以官方條款為準。

### 3.9 防火牆：託管 WAF → Coraza WAF

- **對應替代**：Coraza WAF（開源 Web 應用防火牆，可與 Traefik 或反向代理整合）。
- **功能差異**：託管 WAF 提供託管規則集、自動更新、託管監控；自架 Coraza 須自行維護規則集（例如 OWASP 核心規則集的版本）、誤攔率調校、更新流程與監控。規則維護的人力成本不得忽略。
- **授權條款**：Apache-2.0（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否。
- **免費額度限制**：不適用（自架）。

### 3.10 DNS：Route 53 → Cloudflare DNS

- **功能差異**：兩者皆為託管 DNS，功能差異較小；差異在於整合生態系（託管雲服務的整合）、進階路由功能與支援管道，須以官方文件為準。DNS 遷移須有停機與快取（TTL）計畫，不得以切換完成代替驗證。
- **授權條款**：專有免費服務方案，服務條款以官方當期條款為準，待查證。
- **是否自架**：否。**是否需額外硬體**：否。
- **免費額度限制**：有，免費 DNS 額度以官方當期公告為準，待查證。
- **預估持續性成本**：待查證（網域註冊費另計，見第 4 節）。
- **成熟度**：Cloudflare DNS 為成熟的託管 DNS 服務。

### 3.11 憑證：Certificate Manager → Let's Encrypt

- **對應替代**：Let's Encrypt 免費憑證，搭配自動續期（例如 certbot 或 Coolify／Traefik 的整合）。
- **功能差異**：託管憑證管理提供自動核發、續期、部署整合；Let's Encrypt 憑證有效期較短，須可靠的自動續期流程，續期失敗時須有告警與備援流程。萬用字元與多網域憑證的申請方式，須以官方文件為準。
- **授權條款**：免費憑證服務，服務條款以官方當期條款為準，待查證。
- **是否自架**：否（免費憑證服務，續期自動化自架）。**是否需額外硬體**：否。
- **免費額度限制**：有，憑證有效期與申請頻率限制以官方當期公告為準，待查證。
- **預估持續性成本**：待查證（憑證本身免費，自動續期維運成本另計）。
- **成熟度**：Let's Encrypt 為成熟的免費憑證服務，廣泛使用；自動續期的可靠性為關鍵，不得以首次核發成功代替長期驗收。

### 3.12 身分驗證：Cognito → Keycloak

- **對應替代**：Keycloak 自架身分與存取管理，Realm／Client／角色概念，詳見 `docs/architecture/IDENTITY_AND_PERMISSIONS.md`。
- **功能差異**：託管身分服務提供託管使用者池、託管 UI、自動擴充；自架 Keycloak 須自行處理高可用、備份、升級、主題客製與效能調校。Keycloak 的功能完整度高，但維運複雜度高於託管服務。
- **授權條款**：Apache-2.0（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器成本）。
- **成熟度**：Keycloak 為成熟的開源身分管理服務，社群與文件完整；正確設定（Realm 隔離、Client 設定、角色對應）為安全關鍵。

### 3.13 反向代理與閘道：API Gateway → Traefik

- **對應替代**：Traefik 反向代理與邊緣路由器，搭配 Docker Compose 服務探索。
- **功能差異**：託管閘道提供託管節流、認證整合、使用量計畫；Traefik 偏向反向代理與路由，節流、認證、請求驗證須以中介軟體（Middleware）與後端檢查補齊，不得以 Traefik 的存在代替後端授權檢查。
- **授權條款**：MIT（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器成本）。
- **成熟度**：Traefik 為成熟的開源反向代理，廣泛用於容器部署。

### 3.14 訊息佇列與通知：SQS／SNS → NATS JetStream

- **對應替代**：NATS JetStream（NATS 的持久化訊息串流），用於背景任務、事件分發與通知佇列。
- **功能差異**：託管佇列與通知服務提供託管耐久性、死信佇列、推播整合；自架 NATS JetStream 須自行處理持久化、複寫、死信處理與監控。推播通知本身仍須經 FCM／APNs，NATS 不代替推播服務。
- **授權條款**：Apache-2.0（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器成本）。
- **成熟度**：NATS 為成熟的開源訊息系統，JetStream 為其持久化串流功能；大規模部署的效能須以實測為準。

### 3.15 CI／CD：CodePipeline → GitHub Actions

- **對應替代**：GitHub Actions（CI／CD，含建置、測試、部署流程）。
- **功能差異（功能受限免費）**：託管管線提供託管建置環境與整合；GitHub Actions 的免費額度（執行分鐘數、儲存）以官方當期公告為準，待查證，私有儲存庫與額外執行時間可能收費。iOS 建置須走 macOS runner，runner 的額度與成本須特別評估，待查證。
- **授權條款**：專有託管 CI 服務，服務條款以官方當期條款為準，待查證。
- **是否自架**：否（託管 CI 服務，可搭配自架 runner，方向待定案）。**是否需額外硬體**：否（自架 runner 方向待定案）。
- **免費額度限制**：有，以官方當期公告為準，待查證。
- **預估持續性成本**：待查證（超出免費額度的成本）。
- **成熟度**：GitHub Actions 為成熟的 CI／CD 服務，廣泛使用。

### 3.16 基礎設施即程式碼：Terraform → OpenTofu

- **對應替代**：OpenTofu（Terraform 的開源分支方向，相容多數 Terraform 設定與提供者）。
- **功能差異**：OpenTofu 為社群主導的分支，授權與治理模式不同；與 Terraform 的相容性、提供者生態系、版本更迭，須以實測為準。基礎設施即程式碼的狀態管理、遠端狀態儲存，須自行設定（例如自架狀態後端），不得以工具本身代替狀態管理設計。
- **授權條款**：Mozilla Public License 2.0（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：否（工具本身）。**是否需額外硬體**：否。
- **免費額度限制**：不適用。
- **預估持續性成本**：待查證（工具免費，維運人力另計）。
- **成熟度**：OpenTofu 為較新的分支，社群成長中，長期維護須持續觀察；自架部署以 Docker Compose＋Coolify 為主，OpenTofu 的適用範圍待部署文件定案。

### 3.17 即時通話：LiveKit Cloud → LiveKit Community Edition 自架

- **對應替代**：LiveKit Community Edition 自架（SFU），保留一對一／多人、螢幕分享、房間與參與者、STUN／TURN、SFU、品質監控。
- **功能差異（非完全等價，須特別評估）**：託管通話服務提供全球邊緣節點、託管 TURN、自動擴充、服務等級承諾；自架須自行處理公網部署、TURN 伺服器部署與頻寬、SFU 擴充、品質監控與容錯。TURN 頻寬為主要持續性成本之一，隨通話量與媒體品質而定，金額待查證。公網部署須處理 NAT、防火牆、憑證與監控，不得以本機測試代替公網驗收。
- **授權條款**：Apache-2.0（以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：是，通話併發與 TURN 頻寬須評估伺服器與頻寬；是否需 GPU，待實測（媒體轉碼方向待定案）。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器＋TURN 頻寬成本，為主要持續性成本之一）。
- **成熟度**：LiveKit Community Edition 為成熟的開源即時通訊伺服器，廣泛用於自架部署；自架的公網部署與頻寬管理為關鍵，不得假設與託管服務等價。

### 3.18 AI：雲端 AI API → Ollama＋vLLM＋LocalAI 優先＋AI Provider Adapter

- **對應替代**：Ollama（模型管理與推理）＋vLLM（高吞吐推理）＋LocalAI（相容介面閘道，方向）優先，外部 AI API 經 AI Provider Adapter 可選擴充；向量檢索用 pgvector（已定案，見 ADR-017；評估比較見第 3.19 節）。
- **功能差異（非完全等價）**：託管 AI API 提供前沿模型、託管擴充、按量計費；本地模型的能力、品質、語言覆蓋與推理速度，取決於模型規模與硬體，不得假設本地模型與前沿託管模型等價。模型規模越大，硬體需求越高（見 AI_DATA_POLICY 第 10 節，全部區間待查證／待實測）。外部擴充的資料邊界、成本與授權，須經使用者決定。
- **授權條款**：Ollama 為 MIT；vLLM 為 Apache-2.0；LocalAI 為 MIT（皆以官方儲存庫當期授權文件為準，待查證；模型本身的授權另計，須以各模型當期授權為準，待查證）。
- **是否自架**：是（本地部分）。**是否需額外硬體**：是，GPU／VRAM 需求見 AI_DATA_POLICY 第 10 節，待查證／待實測；不得假設一般伺服器跑得動所有模型。
- **免費額度限制**：不適用（本地部分）；外部部分以供應商額度為準，待查證。
- **預估持續性成本**：待查證（本地：伺服器＋GPU 成本；外部：供應商按量計費）。
- **成熟度**：Ollama 與 vLLM 為成熟且快速發展的開源推理工具，社群活躍但版本更迭快，模型相容性須以實測為準；LocalAI 為成長中的相容閘道，功能覆蓋須以實測為準。

### 3.19 向量資料庫：付費向量服務 → pgvector（已決議採用 pgvector，見 ADR-017；本節比較內文保留為評估紀錄）

- **對應替代**：Qdrant（專用向量資料庫）或 pgvector（PostgreSQL 向量擴充），二選一或搭配；已決議採用 pgvector，見 ADR-017（本節比較內文保留為評估紀錄）。
- **功能差異**：託管向量服務提供託管擴充、託管索引管理；自架 Qdrant 須自行處理擴充與備份，pgvector 須在 PostgreSQL 內管理向量索引，兩者的查詢效能、索引類型與擴充能力不同，須以實測與 RAG 需求定案。權限隔離與刪除同步，須以後端檢查為準，不得僅靠向量資料庫的隔離。
- **授權條款**：Qdrant 為 Apache-2.0；pgvector 為 PostgreSQL License（皆以官方儲存庫當期授權文件為準，待查證）。
- **是否自架**：是。**是否需額外硬體**：否，向量規模擴大時須評估記憶體與儲存。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器成本）。
- **成熟度**：Qdrant 與 pgvector 皆為成熟的開源向量方案，社群完整；選型須以 RAG 規模與查詢需求實測後定案。

### 3.20 錯誤追蹤：Sentry 託管 → GlitchTip 自架

- **對應替代**：GlitchTip 自架錯誤追蹤（相容 Sentry 協定的方向），用於前端與後端的錯誤收集。
- **功能差異**：託管錯誤追蹤提供託管儲存、進階分析、整合與支援；自架 GlitchTip 的功能覆蓋（例如效能監控、進階查詢）可能較託管服務受限，須以實測為準。錯誤資料不得含敏感明文、Token 或 E2EE 明文（見 AI 與安全文件）。
- **授權條款**：以官方儲存庫當期授權文件為準，待查證。
- **是否自架**：是。**是否需額外硬體**：否。
- **免費額度限制**：不適用（自架）。
- **預估持續性成本**：待查證（伺服器＋儲存成本）。
- **成熟度**：GlitchTip 為成長中的開源錯誤追蹤工具，社群較託管服務小，長期維護須持續觀察。

## 4. 仍可能付費項目（不得宣稱零成本）

下列項目無免費或開源等價替代，或替代無法完全滿足需求，仍可能付費。金額一律寫「待查證」。

| 項目 | 說明 | 原因／備註 |
|---|---|---|
| 網域 | 網域註冊與續費 | 須向網域註冊商付費，金額以註冊商當期公告為準，待查證 |
| 伺服器 | 自架主機的運算、儲存、頻寬、備援 | 全部自架方案皆須自負伺服器成本，金額取決於主機規格、區域、流量與備援設計，待查證 |
| 簡訊 OTP | 手機驗證碼簡訊發送 | 無免費的簡訊發送管道；供應商待決定（NQ-02），成本待查證；須評估 Email 驗證與驗證器應用程式作為替代的覆蓋範圍 |
| Apple Developer | Apple 開發者帳號年費 | 上架 App Store 的必要條件，金額以 Apple 當期公告為準，待查證 |
| Google Play 上架 | Google Play 開發者帳號費用 | 上架 Google Play 的必要條件，金額以 Google 當期公告為準，待查證 |
| 外部 AI API | 可選擴充的外部模型供應商按量計費 | 僅在使用者決定啟用外部路徑時產生，金額以供應商當期計價為準，待查證；本地優先路徑不產生此項成本 |
| TURN 頻寬 | LiveKit 自架的 TURN 中繼頻寬 | 通話媒體經 TURN 中繼時產生頻寬成本，隨通話量而定，金額待查證；為主要持續性成本之一，須特別評估與監控 |
| 監控與告警通知 | 告警通知管道（如簡訊、電話）的費用 | 告警管道待決定（OQ-12），若採用簡訊或電話通知，成本待查證 |
| 備份與異地備援 | 異地備份儲存與頻寬 | 自架備份的異地儲存可能產生額外成本，金額待查證；備份策略待定案 |

## 5. 無法完全替代的服務及原因

| 服務方向 | 無法完全替代的原因 |
|---|---|
| 簡訊 OTP | 簡訊發送依賴電信網路，無開源自架的免費發送管道；Email 驗證與驗證器應用程式可部分替代，但無法完全覆蓋僅有手機號碼的使用者情境 |
| 應用商店上架（Apple／Google） | 上架資格與審查由商店方控制，開發者帳號費用為必要條件，無替代 |
| 網域註冊 | 網域註冊由註冊商體系控制，無免費的正式網域註冊管道（免費子網域方向不在本文件承諾範圍內） |
| 前沿託管 AI 模型 | 本地模型的品質、語言覆蓋與推理能力，與前沿託管模型不完全等價；是否採用外部模型，須經品質實測與資料邊界確認後決定 |
| 託管通話的全球邊緣與 TURN 頻寬 | 自架 TURN 的頻寬與全球覆蓋，取決於自架主機的位置與頻寬，無法直接等價於託管服務的全球邊緣網路；TURN 頻寬成本仍須負擔 |
| 託管資料庫的自動容錯與時間點還原 | 自架 PostgreSQL 的容錯與還原能力，取決於營運方的備份與複寫實作，無法直接等價於託管服務的承諾；須以還原測試證明能力 |
| 託管內容分發的免費額度上限 | Cloudflare Free 的免費額度與功能受限，流量上量後須評估升級或替代方案，無法假設免費額度可支撐任意流量 |
| 推播服務（FCM／APNs） | 推播本身由平台方提供，免費但受平台條款約束；NATS 不代替推播服務，推播內容的隱私邊界見通知文件 |

## 6. 持續性成本的管理要求

1. 成本監控：伺服器、頻寬、儲存、外部 API 的用量，須納入 Prometheus＋Grafana＋Loki 監控，設定預警門檻（門檻待定），達到門檻時提出方案供使用者決定，不得靜默超額。
2. 額度查證：Cloudflare Free、GitHub Actions、Let's Encrypt 等免費額度，須以官方當期公告為來源逐項記錄，寫入營運文件；查證前不得對外宣稱「免費可用至某量級」。
3. 備份與還原：自架服務的備份策略與還原測試，須留存紀錄；備份失敗時須告警，不得宣稱已具備復原能力而無測試證據。
4. 升級與維護：開源軟體的版本升級、安全性更新、授權變更，須有專責流程；授權變更時須重新評估合規性，不得以舊授權文件代替。
5. 不得宣稱零成本：任何對外或對內的成本說明，須同時列出仍可能付費項目（見第 4 節），不得僅列免費方案而忽略伺服器與付費項目。

## 7. 規格缺口（只列、不補決定）

1. 各項自架服務的伺服器規格、主機數量、部署區域、備援設計尚未定案，成本無法估算。
2. 向量資料庫選型已定案為 pgvector（見 ADR-017）；本地 AI 三者分工、OpenTofu 適用範圍尚未定案。
3. 免費額度（Cloudflare Free、GitHub Actions、Let's Encrypt）的當期數字尚未查證。
4. 簡訊 OTP 供應商、外部 AI API 供應商、TURN 頻寬的計價方式尚未查證。
5. 各項開源軟體的授權條款，須以官方文件覆核，本文件標示的授權皆為方向，待查證。
6. 自架服務的備份、容錯、還原測試計畫尚未定案。
7. Docker Compose 啟動／連線／上傳／訊息／AI 切換／LiveKit／監控的驗證，待 CI 或有 Docker 的環境驗證。
