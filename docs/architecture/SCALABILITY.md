# ETHER 擴充架構（SCALABILITY.md）

> 依據：`~/workspace/ether/SPEC-SOURCE.md` §23（效能與擴充）、頂部「架構調整」一節（2026-11-25 00:33，優先於舊技術棧）、手冊 C／G（環境、即時訊息核心）。
> 本文件只寫擴充架構，不寫應用程式碼。明寫：**未經壓力測試不得宣稱承載數**；不編造 QPS、人數、延遲等效能指標；成本一律寫「待查證」。
> 部署形態為 Docker Compose＋Coolify＋Traefik＋Cloudflare Free 自架（見 `SYSTEM_ARCHITECTURE.md` §3 與 ADR-013），本文件的擴充路徑皆為自架叢集路徑，不得預設受管服務。

## 1. 擴充原則

1. **先量測，後擴充**：擴充決策一律以 Prometheus 指標證據（延遲、佇列積壓、連線數、CPU／記憶體、磁碟、頻寬）為依據，不得以推測或「預先拆分」為由擴充。
2. **無狀態先行**：先擴充無狀態層（API、Gateway、Worker），再擴充狀態層；狀態層擴充須有資料一致性方案，不得先擴充再補一致性。
3. **不得宣稱未測的承載數**：SPEC-SOURCE.md §23 明文——不得在無壓力測試下宣稱可承載特定同時在線數。本文件不寫任何承載數、QPS 或人數目標；壓力測試的場景與通過標準屬測試策略文件範圍。
4. **水平優先於垂直**：單機規格提升（垂直擴充）只作短期緩解，長期路徑一律為水平擴充（副本／分片／叢集），且須證明單點故障已消除。
5. **功能不降級**：擴充不得以關閉功能、降低 E2EE、放寬權限或靜默丟訊息為代價。

## 2. Connection Pool（資料庫連線池）

- PostgreSQL 連線池由 Go 後端統一管理（池大小、逾時、健康檢查的參數待壓測定案，本文件不定數字）；API、Gateway、Worker 各自的池不得互相擠佔（讀寫分離後，寫入池與唯讀池分離）。
- 規則：連線必須歸還（defer 關閉為程式規範）、長交易不得佔用連線、慢查詢須接入 Prometheus 慢查詢指標與 Loki 日誌；連線池耗盡時，API 須回傳明確錯誤（熔斷方向），不得無限等待拖垮全系統。
- 唯讀複本：讀寫分離為資料層擴充的第一步（寫入只走主庫，讀取可走複本）；複本延遲下的讀取一致性語義（讀己之寫）須在 API 層定案（寫後讀走主庫的方向），不得假設複本即時同步。
- 自架注意：PostgreSQL 自架須有備份、WAL 歸檔、故障轉移演練（細節待維運文件）；複本數增加的成本（主機與儲存）待查證。

## 3. Valkey 快取策略

Valkey（自架）承接原快取職責：快取、Session 輔助狀態、Presence、Rate Limit 計數、Gateway 連線狀態輔助。

### 3.1 快取內容與失效

| 快取內容 | 來源 | 失效策略 |
|---|---|---|
| 使用者公開檔案、群組／社群公開資訊 | PostgreSQL | 寫入後失效（write-through 不得先寫快取）；失效失敗須可重建（回源） |
| 對話列表摘要、未讀計數輔助 | PostgreSQL＋事件 | 事件驅動失效（NATS 事件觸發失效）；計數以 PostgreSQL 為準，快取只作加速，不得作為唯一計數來源 |
| 搜尋熱門結果（可選） | Meilisearch | 短效快取＋失效，不得快取未過濾的結果（權限過濾在 API 層，見 `DATA_FLOW.md` §8） |
| Rate Limit 計數 | 即時計數 | 滑動／固定窗口由實作定案，計數遺失只影響限流嚴格度，不得影響正確性 |
| Session／Presence 輔助狀態 | Keycloak／PostgreSQL | 可遺失、可重建；Session 唯一紀錄在 `user_sessions`，不得只存 Valkey |
| Gateway Registry 輔助 | 連線狀態 | 可遺失；重啟後由重連恢復重建，不得假設 Registry 持久 |

### 3.2 快取原則

- 快取未命中一律回源，不得回傳空結果冒充「無資料」；快取穿透（大量不存在鍵）須有空值快取或布隆過濾的方向（實作待定，不得編造）。
- 快取雪崩：失效時間須加抖動，不得全量同時失效；Valkey 故障時，系統須降級為直接讀 PostgreSQL（可慢、不可錯），不得全體拒絕服務。
- Valkey 叢集化為資料層擴充的一步（見 §7）；叢集化前，單節點 Valkey 的故障即快取全失，須以回源降級承接，不得假設快取永遠可用。
- 不得在 Valkey 存放明文密碼、Token 明文、E2EE 明文（見 `SECURITY_ARCHITECTURE.md` §3.2）。

## 4. NATS 佇列（NATS JetStream）

- NATS JetStream 為唯一的事件／佇列平面：Outbox 投遞、推播扇出、搜尋索引同步、Bot Webhook、媒體處理、離線佇列的伺服器側（見 `DATA_FLOW.md`）。不得另建一套佇列（例如資料庫輪詢）與之並存。
- 消費模型：Consumer Group＋持久訂閱；Worker 水平擴充即增加 Consumer 副本；消費必須冪等（事件 ID 去重），投遞為至少一次，不得假設恰好一次。
- 背壓（Backpressure）：佇列積壓達門檻時，Gateway 須對發送端施加背壓（延遲 ACK／拒絕新寫入的方向，細節待 Phase 05 定案），不得無限接受寫入拖垮佇列；積壓指標接入 Prometheus（見 ADR-012）。
- 死信佇列（DLQ）：重試耗盡的事件進 DLQ，由維運／Worker 補償處理，不得無聲丟棄；DLQ 的保留與重放流程待維運文件定案。
- NATS 叢集化：自架叢集（Raft 方向，節點數與持久化設定待查證）；叢集化前，單節點 NATS 故障即事件投遞中斷，已持久化的訊息本體仍在 PostgreSQL，恢復後須可由 Outbox 重放，不得假設 NATS 永不故障。
- 串流保留：JetStream 串流的保留期限與磁碟上限待查證（自架主機磁碟），不得編造；保留期滿的事件不得影響已寫入 PostgreSQL 的業務資料。

## 5. Cursor 分頁

- 全部列表（訊息、對話、成員、搜尋結果、動態、通知）一律 Cursor 分頁，不得用 OFFSET 大分頁（OFFSET 在大資料量下的效能衰減為已知方向，細節待壓測驗證）。
- 訊息分頁以 Sequence／Cursor（每對話）為準（見 `DATA_FLOW.md` §3－§4）；Cursor 須不透明（不得讓用戶端拼裝 SQL 條件），且須與排序鍵一致（排序鍵由 ERD／API 標準文件定案）。
- 分頁大小的預設與上限待產品／API 文件定案，本文件不定數字；超過上限的請求須回傳明確錯誤，不得靜默截斷。
- 搜尋分頁：Meilisearch 的分頁與 Cursor 語義須在 Search 模組內統一（不得讓用戶端直接拼 Meilisearch 分頁參數），權限過濾在 API 層、回傳前執行，不得以分頁為由跳過過濾。

## 6. 索引原則

### 6.1 PostgreSQL 索引

- 全部 §20 資料表須有 PK、FK、Unique Constraint、必要索引（SPEC-SOURCE.md §20）；索引清單由 ERD 文件逐表定案，本文件只定原則：
  - 高併發寫入表的索引須克制（每多一個索引即多一份寫入成本），索引增減須以慢查詢證據為依據，不得「先建一堆再說」。
  - 訊息查詢的主索引方向為（對話、Sequence／時間）複合索引；成員查詢、回條查詢、搜尋輔助查詢各有對應索引，細節待 ERD。
  - 唯一約束即冪等防線（`client_message_id` 方向、好友配對方向），不得以應用層檢查代替唯一約束。
- 索引維護：定期以 `EXPLAIN`／慢查詢日誌覆核（頻率待維運文件），無用索引須移除，不得長期累積。

### 6.2 Meilisearch 索引

- Meilisearch 索引為 PostgreSQL 的投影（見 `DATA_FLOW.md` §8），索引結構由 Search 模組定；索引欄位只含搜尋所需欄位，不得全文索引 E2EE 明文、私密欄位或 Token。
- 索引同步為事件驅動、冪等投影；索引遺失須可由 PostgreSQL 重建；重建期間搜尋可降級，不得謊稱結果完整。
- Meilisearch 節點增加為資料層擴充的一步；分片／複本策略待查證（自架），不得編造。

### 6.3 向量索引（AI，待定）

- 向量檢索走 pgvector（已定案，見 ADR-017）；本文件不定向量索引結構、維度或距離函式；RAG 索引的權限隔離（每使用者的知識庫隔離）與刪除同步為強制要求，不得以後補。

## 7. MinIO＋Cloudflare Free CDN 與物件儲存

- 物件儲存為 MinIO 自架（見 `MODULE_BOUNDARIES.md` Media 模組擁有物件命名空間）；媒體原檔、縮圖、轉碼檔、加密備份檔本體皆存 MinIO，不得直連用戶端可寫的公開 Bucket。
- 分發經 Cloudflare Free CDN（MinIO 為來源）：熱門媒體經 CDN 快取，簽名授權仍由 API 核發（CDN 不得繞過授權檢查；簽名 URL 的效期與 CDN 快取期的關係待部署文件定案）。
- MinIO 擴充：多節點／糾刪碼（Erasure Coding）方向，節點數與儲存策略待查證（自架主機磁碟）；儲存用量指標接入 Prometheus（見 ADR-012）；儲存滿載時，上傳須明確拒絕，不得靜默失敗或覆寫舊檔。
- 生命週期：孤兒附件、逾時上傳、已刪除檔案的衍生檔清理策略待 ERD／維運文件定案（清理週期不得編造）；清理不得刪除仍被參照的檔案。

## 8. Background Jobs（Worker）

- 全部背景工作（推播扇出、索引同步、媒體縮圖／轉碼／掃描、Bot Webhook、清理、報表聚合）皆經 NATS＋Worker，不得以 Cron 直連資料庫輪詢代替佇列（Cron 只作觸發器，工作本體仍走 NATS 事件）。
- Worker 須冪等、可重試、可水平擴充（見 §4）；長時間工作須有進度與逾時，不得佔用 API 請求執行緒。
- 媒體處理的轉碼／縮圖為 CPU 密集工作，Worker 副本的資源配額（CPU／記憶體）待壓測定案；轉碼失敗不得阻塞訊息寫入（訊息與媒體狀態分離，見 `DATA_FLOW.md` §5）。
- AI 背景工作（索引、摘要）亦走同一 Worker 平面，不得另建一套 AI 工作佇列；AI 工作的 Token 統計與資源管理見 AI 規範文件。

## 9. 水平擴充與多區域部署路徑（自架）

擴充順序見 `SYSTEM_ARCHITECTURE.md` §4.2，本節補狀態層的自架細節：

1. **應用層水平擴充**：API／Gateway／Worker 副本數增加，Traefik 分流；Gateway 跨副本路由經 Valkey／NATS；Coolify 為副本管理平面（見 ADR-013）。
2. **狀態層叢集化**：PostgreSQL（主從複本→故障轉移）、Valkey（叢集）、NATS（叢集）、Meilisearch（節點增加）、MinIO（多節點）；每一步皆須有備份與故障演練，不得只擴充不演練。
3. **模組拆分**：僅在介面穩定且擴充需求分化時拆分（見 `SYSTEM_ARCHITECTURE.md` §4.2 第 4 步）；拆分後內部呼叫走 gRPC，事件走 NATS，資料表歸屬不變。
4. **多區域部署**：最後一步，須先解決跨區資料一致性、Sequence 分配、E2EE 金鑰同步、媒體複製、法規遵循；細節待查證，不得在 Phase 00 宣稱已解決。Cloudflare Free 的多區域分發不等於後端多區域部署，不得混為一談。

自架約束：全部叢集化皆為自架主機上的叢集，主機規格、數量、成本皆待查證（伺服器為仍可能付費項目）；不得以「上雲即自動擴充」的心態規劃自架擴充——每一層的擴充皆須有人為操作與驗證步驟（見部署／維運文件）。

## 10. LiveKit CE 擴充評估（交叉引用 `SYSTEM_ARCHITECTURE.md` §9）

- LiveKit CE 自架 SFU 的擴充路徑：單節點 SFU → 多節點（房間分片／級聯方向，細節待 LiveKit CE 官方文件查證）；房間與參與者的路由須以房間為單位，不得跨節點拆分同一房間的媒體（方向待查證）。
- TURN 頻寬為擴充的關鍵變數：中繼率上升時頻寬與 CPU 消耗同步上升；TURN 頻寬列為仍可能付費項目，成本待查證（見 ADR-011）；監控須含 TURN 中繼率、通話建立成功率、媒體延遲（見 ADR-012）。
- 品質監控與擴充決策掛鉤：通話品質指標惡化時，優先檢查 TURN／頻寬與 SFU 負載，不得直接認定為用戶端問題。

## 11. 架構缺口

1. 全部擴充參數（連線池大小、快取效期、分頁上限、NATS 保留、索引清單）皆未定，待壓測與 ERD／API 文件定案，不得編造。
2. PostgreSQL 故障轉移、Valkey／NATS 叢集的具體拓撲待部署文件定案（自架）。
3. 壓力測試的場景、資料量、通過標準未定（屬測試策略文件）；未經壓力測試不得宣稱承載數——本文件無任何承載數宣稱。
4. 向量庫已定案為 pgvector（見 ADR-017）；AI 資源評估未定（見 ADR-009）。
5. 多區域部署方案未定。
